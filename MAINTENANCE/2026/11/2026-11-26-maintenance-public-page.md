## 3. 公开生成口径

1. 只把 `MAINTENANCE/YYYY/MM/YYYY-MM-DD-英文主题.md` 识别为事件；`MAINTENANCE/README.md` 保留为规则文档，不列入事件目录。日期、年月目录、首行标题、状态和正文开始日期不一致时阻断构建，不静默遗漏。
2. 事件按开始日期及源文件路径倒序排列。左侧提供全页目录，右侧保留每篇全文和 GitHub 原始日志链接；不增加依赖 JavaScript 的折叠、加载或搜索控件。
3. 内置安全 Markdown 子集渲染标题、段落、列表、表格、围栏代码、行内代码、粗体、引用和链接，不引入新的 Python 包。原始 HTML 一律转义；不安全链接不生成 href。
4. 仓库相对链接按日志所在目录归一化后改写为 GitHub `blob/main` 地址，不能在公开站错误解析为站点本地文件；HTTP／HTTPS 外链使用 `noopener noreferrer`。
5. 首页“维护日志”入口紧跟“非创业技术储备”。新页面使用独立 canonical 和文字版 OG，类型为 `website`，不生成 Article JSON-LD。
6. sitemap 继续从真实 HTML 集合生成，因此当前由57个公开 HTML 增至58个。维护日志没有可靠的单页内容修改日期，不使用构建日伪造 `lastmod`。

## 5. 问题、根因与处理

### 5.1 带括号链接的右括号残留

- 现象：首轮安全测试中，`[不安全链接](javascript:alert(1))` 的危险 href 没有生成，但正文留下一个多余右括号。
- 根因：初版行内链接正则在第一层右括号即停止，没有识别链接目标内部的一层平衡括号。
- 处理：链接目标改为支持一层平衡括号；不安全目标仍只保留文字，安全测试继续断言没有 `javascript:` 和可执行脚本。
- 验证：85项测试全部通过，带括号安全／不安全链接均有回归样本。

### 5.2 列表断言误把格式换行当内容差异

- 现象：首轮另一失败要求整个有序列表挤在一行，而生成器为可读 HTML 在列表项间输出换行。
- 处理：没有改动正确列表输出；测试改为匹配允许空白的有序列表结构，继续验证两项内容及顺序。

### 5.3 验收工具的三次取样误报

- 普通正文残留 Markdown 检查最初把行内代码中的 `[不安全链接](javascript:alert(1))` 示例当成未解析链接；排除 `code`／`pre` 后检查真实正文通过，没有删改安全样本。
- 目录点击后立即读取位置会落在 CSS 平滑滚动中途；改为等待目标到达视口，或确认页面已到底且目标仍可见后再断言。禁用脚本的页面改用主动轮询取样，最终4个锚点均通过。
- 桌面首页左侧栏是带内部滚动的 sticky 区域，整页截图按文档坐标裁剪栏底链接会得到空白；改为先把维护日志入口滚入侧栏可视区，再截图并执行真实点击。这是截图取样问题，不是入口缺失。
