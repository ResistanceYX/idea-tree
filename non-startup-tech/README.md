# 非创业技术设想储备区

本目录用于临时存放不属于创业项目的非创业技术设想，是尚未启用的隔离储备区，不是正式节点目录。

## 当前边界

- 本目录文件不适用 `nodes/` 的正式节点格式，不强制填写复活状态、重启预算、死法分类或商业及社会价值评估。
- 本目录不参与 G01 正式节点校验，不进入 G02 生成的 `INDEX.md`，也不接入现有科技树。
- 本目录不属于根 README 月度全检所称的正式节点 YAML；储备文件是否保留、何时启用，由主编另行决定。
- 文件被存放在这里，不表示其技术可行性、合法性、价值或风险结论已经通过审核。
- 储备文件至少应写清标题、设想来源、记录日期、当前结论和记录边界，避免把原始设想误写成既定事实。
- 静态站“非创业技术储备”页只展示 `public_reserve.yaml` 白名单中、经主编确认公开的标题和一句话，并提供GitHub原文链接。新增储备文件默认不登记；未列入白名单的文件不得进入该页。
- 元数据导航不属于正式启用：储备文件仍不进入正式节点编号、统计、INDEX、REVIEW、科技树、公开JSON、首页搜索或正式节点详情页，公开展示也不等于通过实质审核。

## 导航白名单维护

- 白名单文件为本目录的 `public_reserve.yaml`；只填写本目录直接下级 `.yaml` 文件名，不写完整路径。
- 新增储备稿经主编确认后，在 `公开导航` 列表添加一行 `- 文件名.yaml`；删除该行只取消静态站导航，不删除GitHub原文或提交历史。
- 列表顺序即页面顺序。新增YAML但未登记时不会出现在静态站；白名单缺失或格式异常、重复登记、指向缺失文件、嵌套路径或元数据异常会阻断构建。

## 日后正式化

元数据导航不改变储备区的隔离性质。储备档案如需成为正式节点，仍须单独制定或补齐字段、分类、证据、审核、校验与索引规则，并逐份人工复核；不得仅通过把文件移入 `nodes/` 来直接启用。
