## 1. 背景与目标

本轮按主编提供的《澄樾执行清单：可见度工程与排版收尾》审议并实施。目标是为既有公开静态站补齐 sitemap.xml、llms.txt、canonical、文字版 Open Graph、robots.txt 和正式节点 Article JSON-LD，同时把第六轮排版中仍需保持的布局约束固化成测试。

起稿时重新核对云端 main：第六轮维护日志已经入库并标为完成；`c1f9ecd14aff2b7d678909de9c31890479bfd436` 相比上一轮云端复核基线只新增该日志的完成收尾，不存在需要重复交付的第六轮“已完成”替换文件。当前工作副本有51个正式节点、277条死法、390个不同原始链接、876次链接出现，修改前有75项单元测试。清单中“第六轮排版进行中”和“维护日志第二篇”等描述属于制定时的旧状态，本篇实际是维护日志目录中的第三篇。

本轮不修改节点事实、编号、id、双向关系、复核履历、证据或判断性内容，不处理22条既有证据警告，不制作 OG 图片，不增加 FAQPage，也不引入新的前端框架、后端、数据库或额外构建依赖。技术可见度不等于搜索引擎收录、排名、引用或实际传播效果，也不替代首发介绍帖 Issue #7。

## 2. 审议后的语义调整

1. **不重复重做第六轮排版。** 只补充文本溢出、长标题与长 id 换行、布局子项收缩和科技树局部横向滚动等可机检不变量，并执行指定视口验收。
2. **sitemap 只收录实际公开 HTML。** 当前没有独立的公开“死法分类页”和“复核清单页”，不能为它们编造 URL。死法分类法与 `REVIEW.md` 作为 GitHub 公开文档进入 llms.txt。
3. **`lastmod` 不使用每次构建日。** 节点取审核日期与最新复核后日期中的较晚者；首页和科技树取当次节点内容日期中的最晚者；其他无法推得真实内容日期的页面省略该字段。
4. **OG 类型按页面性质区分。** 只有正式节点详情页使用 `article`，其他公开页使用 `website`。没有经审核的预览图，因此不输出虚假 `og:image`，文字版 OG 也不称为完整富图分享卡片。
5. **Article 不伪造首次发布日期。** 现有审核日期可能在实质复核后更新，不能可靠表示首次发布时间，因此只输出有档案依据的 `dateModified`，不输出 `datePublished`。
6. **llms.txt 采用当前 v2 结构。** 输出 H1、blockquote 摘要、公开说明和 H2 分节链接；全站 HTML 增加 `rel="describedby"` 发现链接。本期不扩做全站 Markdown 镜像或 `llms-full.txt`。
7. **robots.txt 记录项目子路径边界。** 生成文件属于 `https://resistanceyx.github.io/idea-tree/robots.txt`，不等同于 `https://resistanceyx.github.io/robots.txt`。起稿时实际检查后者返回404；若未来需要源站根级控制，应另案评估用户站点仓库，本工作包不声称已经替代根级文件。
8. **Issue 只形成本地 G20 草案。** 不直接创建 GitHub Issue，不预写 Issue 编号；开启 Issue 也不代表实施、部署或验收完成。

## 4. 生成物的实际口径

### 4.1 sitemap.xml

本次真实构建共有57个公开 HTML：51个正式节点详情页、首页、科技树、特别鸣谢、实现仓登记、储备区公开导航和1个白名单公开文献摘录页。sitemap 含57个唯一 URL，与当次输出目录中的 HTML 集合一致，不包含 YAML、JSON、私有证据、储备区原文或不存在的页面。

更新提示保持克制：首页为 `weekly`／`1.0`，科技树为 `weekly`／`0.8`，节点详情为 `monthly`／`0.8`，白名单摘录页为 `yearly`／`0.3`，其他公开页为 `monthly`／`0.5`。这些提示不是收录或排名承诺。

### 4.2 canonical、OG 与 llms.txt

每页只有一个绝对 canonical，`og:url` 与其一致；首页规范地址为 `https://resistanceyx.github.io/idea-tree/`，其他页面按实际相对路径生成，不带 query 或 hash。每页输出 `og:title`、`og:description`、`og:url`、`og:type`，并有一个指向公开 llms.txt 的 `rel="describedby"`。

标题和简介进入元数据前按既有 `searchable_text()` 规则整理软换行，避免多行“一句话”在 HTML 属性中产生原始换行，同时保留中英文词边界。llms.txt 只列节点索引、科技树、实现仓登记、死法分类法和复核清单等公开入口，不包含私有证据或内部工作材料。

### 4.3 Article JSON-LD

正式节点详情的最小字段为 `headline`、`description`、`dateModified` 和 `author`。`author.name` 直接来自节点审核人，当前51个节点均为 `ResistanceYX`；日期来自真实审核日期或最新复核后日期。0051 的 `dateModified` 为 `2026-11-25`，没有 `datePublished`。

序列化会转义 `&`、`<`、`>`、U+2028 和 U+2029。安全测试使用含 `</script><script>` 的标题和简介，确认源文本不能闭合或逃逸 JSON-LD 脚本。未添加 FAQPage、评分、评论、虚构图片或商业成果字段。

### 4.4 robots.txt

实际内容为 `User-agent: *`、`Allow: /` 和指向项目站绝对地址的 `Sitemap:` 行；不含 `Disallow`，不为 GPTBot、ClaudeBot 等单独写规则。该许可规则只描述本项目生成文件，不扩张为对整个 `resistanceyx.github.io` 源站的控制声明。

## 6. 问题、根因与处理

### 6.1 测试插入时误删函数声明

- 现象：插入头部元数据解析器后，测试文件中的 `def node_text(` 一度被误删，留下孤立参数。
- 处理：运行测试前恢复函数声明；随后语法检查和测试正常，没有通过删测试绕过问题。

### 6.2 llms.txt 测试首次失败是夹具缺文件

- 现象：测试中的 `REVIEW.md` 公开链接无法映射到临时仓库文件。
- 根因：临时测试仓库原本没有建立 `REVIEW.md` 和分类法标题，不是实际云端缺文件，也不是生成链接错误。
- 处理：补齐临时测试夹具，不删除真实项目需要的复核链接；随后新测试和全量测试通过。

### 6.3 首次完整浏览器回归因辅助路径中止

- 现象：第一轮完整矩阵在排序全文索引阶段读取默认 `_site/data/search-index.json` 时找不到文件，已完成的页面断言不计为整轮通过。
- 根因：工作副本当时只生成了独立验收输出目录，尚未生成浏览器辅助脚本预期的默认 `_site`；这不是公开站功能断言失败。
- 处理：实际生成默认 `_site` 后从头重跑完整矩阵，最终395项全部通过。第一次中止保留为过程记录，不改写成成功。

### 6.4 多行“一句话”进入元数据

- 现象：真实构建抽查发现0051的 description 和 OG 摘要含节点原文软换行。
- 处理：页面标题、简介和 Article 对应字段统一经 `searchable_text()` 整理；增加多行中英文样本测试，并在最终90项浏览器检查中验证 OG 摘要为单行。

### 6.5 本地 HTTP 服务首次未启动

- 现象：首轮浏览器验收前的 shell 后台服务没有成功启动。
- 处理：改用验收进程内的线程 HTTP 服务，避免后台命令优先级和进程生命周期干扰；后续真实浏览器验收正常。该问题不涉及仓库代码或公开站。

### 6.6 既有证据警告不属于本轮消除对象

22条证据多样性及派生证据警告原样保留。本轮没有逐项实质复核，因此没有为消除警告替换链接、删除证据、修改关系、调整复核日期或改变节点判断。
