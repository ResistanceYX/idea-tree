# idea-tree

> 每个点子只死一次，但死因可以被检索一万次。

这里是一座创业点子的死法档案与科技树。每个节点记录：点子一句话、死因分类、证据链接、可拆零件、死因保质期。

**工作方式**：AI初稿，人类审核定案。
**使用方式**：想出点子，先查再问，问完回写。

## 检索维度（元数据字段）

- 复活状态：死透 | 复活候选 | 已复活（随时间更新，与id无关）
- 创新类型：渐进式 | 突破式 | 破坏式 | 技术应用 | 理论创新（可多选）
- 领域/子领域：先自由填写中文标签，节点满50个后归纳出正式分类法

## 死法分类法 v1.1

| 编号 | 死法 | 说明 |
|---|---|---|
| 1 | 伪需求 | 没人要 |
| 2 | 钱算不平 | 收入覆盖不了成本 |
| 3 | 巨头碾压 | 免费把价格锚点打死 |
| 4 | 政策风险 | 资质、监管红线 |
| 5 | 季节魔咒 | 一年只有一两个月有需求或只在短期内有需求 |
| 6 | 冷启动死锁 | 双边/内容网络起不来 |
| 7 | 信任成本 | 用户不敢信你 |
| 8 | 条件已死 | 当年死于技术/成本，现已翻案（复活候选，单独标注） |
| 9 | 执行人限制 | 创始人约束：时间、能力、决心（v1.1 新增） |

新增死法类别必须更新本表并提升版本号

## 节点格式

示例: [nodes/dafeiyu-cyber-cemetery.yaml](nodes/dafeiyu-cyber-cemetery.yaml)

- id: 全小写、英文、数字、连字符，全局唯一
- 死法: 每条含 类型（必须为上表之一）/ 证据 / 推理 / 置信度
- 死因保质期: 即建议复核日期，一律写YYYY-MM-DD
- 起草AI: AI辅助起草需署名

## 编辑规范（三条铁律）

1.**证据铁律**：每条死法必须有证据；纯内部推演须证明，公开案例必须挂链接。
2.**置信度规则**：纯内部推演封顶“中”，有公开证据链接才可标”高“。
3.**标点与语法**：正文用中文全角标点；YAML键值对用半角冒号加空格，同级缩进对齐。
